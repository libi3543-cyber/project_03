# Natural Language to Windows CMD Translator

פרויקט זה מציג תהליך פיתוח ואיטרציה של פרומפטים (Prompt Engineering) במטרה להמיר הוראות בשפה טבעית (Natural Language) לפקודות שורת פקודה ב-Windows (`cmd.exe`). 

הפרויקט מציג מדרג שיפורים בשלוש גרסאות שונות של פרומפטים (`v1`, `v2`, `v3`), תוך התמודדות עם אתגרי אבטחה, דיוק בתחביר, ושמירה על נתיבים יחסיים.

---

## 📋 תיאור הגרסאות והתפתחות הפרומפטים

1. **גרסה 1 (`v1.txt`) - פרומפט בסיסי (Unconstrained):**
   * המרה בסיסית בלבד ללא מגבלות פורמט או אבטחה.
   * **בעיות שזוהו:** "הזיות" של נתיבי מערכת מוחלטים (`%USERPROFILE%`), הוספת דגלים מיותרים וחסרי אחריות, והחזרת טקסט הסברי מחוץ לפקודה.

2. **גרסה 2 (`v2.txt`) - הגבלת פורמט, מינימליזם ונתיבים (Structured Constraints):**
   * איסור על פורמט Markdown או טקסט נלווה (פלט בשורה אחת בלבד).
   * דרישה להיצמד לנתיבים יחסיים ללא המצאת נתיבי מערכת.
   * כלל מינימליזם: ביצוע הפעולה המינימלית הנדרשת (במיוחד בבקשות צפייה).

3. **גרסה 3 (`v3.txt`) - מנגנון אבטחה והגנה על פקודות רגישות (Safety Block):**
   * הוספת בלוק אבטחה מפורש (`Safety & Destructive Command Block`).
   * הגדרה ברורה של פקודות רגישות (`del`, `taskkill`, `rmdir` וכו') והתרת שימוש בהן רק כאשר המשתמש מבקש זאת במפורש, באופן ממוקד ובטוח.
   * דחייה או החזרת שאילתת מידע בטוחה במקרה של בקשות הרסניות גורפות או עמומות.

## 💡 שני מקרים מעניינים שצפו במהלך פיתוח הפרומפטים

1. **מקרה 1: "המצאת" נתיבי מערכת מוחלטים בבקשות יחסיות (תוקן ב-v2)**
   * **הבעיה:** כאשר התבקש המודל ב-v1 למחוק קבצים זמניים בתיקייה מסוימת (למשל: `"אני רוצה למחוק את כל הקבצים עם סיומת tmp בתיקייה downloads"`), הוא נטה להחזיר נתיב מוחלט ומלא כמו `del "%USERPROFILE%\Downloads\*.tmp"`.
   * **הפתרון:** בגרסה 2 הוספנו כלל מחמיר: *"Use exactly the file names, folder names and extensions the user gave. Do not invent paths. If the user gives a relative name, keep it relative"*. כלל זה גרם למודל להחזיר במדויק את הנתיב היחסי `del downloads\*.tmp`.

2. **מקרה 2: כפילות בין זהירות-יתר לפקודות ניהול מורשות (תוקן ב-v3)**
   * **הבעיה:** בגרסה 2, בעקבות הדגש על מינימליזם ואי-ביצוע שינויים מיותרים, המודל נטה לסרב או להחזיר פקודות לא מדויקות בבקשות לגיטימיות של עצירת תהליכים ממוקדים (כגון `"עצור תהליך רץ בשם notepad.exe"`).
   * **הפתרון:** בגרסה 3 הגדרנו במפורש את גבולות הבטיחות: פקודות ניהול (`taskkill`, `del`) מותרות ומדויקות כל עוד המשתמש הגדיר יעד ממוקד, מפורש ובטוח. שינוי זה איפשר למודל להחזיר `taskkill /im notepad.exe` באופן תקין ובטוח.
